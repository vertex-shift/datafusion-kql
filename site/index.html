Typed KQL goes straight to DataFusion plans and Arrow kernels. No generated SQL. No separate query engine.

KQL query

datatable(Service:string, Duration:long)
  ['api',120,'api',260,'worker',90]
| where Duration > 100
| summarize Requests=count(),
    P95=percentile(Duration,95) by Service

An extension,
not a replacement.

The host application stays in charge. KQL adds a language frontend and expression-local kernels, not another infrastructure layer.

Your tables
Query existing CSV, JSON, Parquet, memory tables, catalogs, and custom TableProviders.
Your runtime
Keep object stores, target partitions, memory pools, spill directories, and application timeouts.
Your optimizer
Native filters, joins, projections, aggregates, and top-k remain visible to DataFusion.
Your functions
Host registrations stay intact. KQL-specific batch functions do not overwrite the session registry.

Try it in a
real Rust session.

Start from the repository. You need Rust 1.94+ and a C compiler for the bundled decimal runtime. No Azure account is required.

Run the quickstart

git clone https://github.com/vertex-shift/datafusion-kql.git
cd datafusion-kql
cargo run --locked --example quickstart

Source-first setup. The package name is datafusion-kql-native; the Rust import is datafusion_kql. The similarly named published datafusion-kql crate is a separate project.

Add it to an existing application

A lazy DataFrame, as usual

use datafusion::prelude::*;
use datafusion_kql::SessionContextKqlExt;

let ctx = SessionContext::new();
let frame = ctx.kql(
    "range x from 1 to 5 step 1
     | summarize Total=sum(x)"
).await?;

// Planning stays lazy.
frame.show().await?;

Read the contract before relying on parity.

Wide datetime/timespan ranges, additional service and query surfaces, seasonal decomposition, period detection, and forecasting remain roadmap work. Sketch blobs use local formats, not Kusto-service formats. Some functions have explicit extension profiles and stricter error handling.
